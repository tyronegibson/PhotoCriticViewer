1. **iPhone remote access** — control/review from phone; **no** heavy processing on device.

5. **Storage** — keep RAW + masters local; previews for remote; stable asset IDs.

## Recommended first prototype (smallest useful change)

**Scope:** remote browse + kick jobs + watch status. **No pipeline rewrite.**

1. Keep the existing Swift control API; add a setting to also bind on Tailscale IP (or Tailscale Serve) **in addition to** localhost. Default remains localhost-only. Toggle off = full rollback.
2. Auth: keep bearer token; do **not** expose unauthenticated public internet.
3. Add/confirm endpoints useful to mobile:
   - `GET /previews/{id}` (or equivalent optimized JPEG/WebP)
   - solid `GET /jobs` (+ job detail/progress)
   - export download path already sketched in `API.md`
4. Serve **one** static mobile-responsive web UI (browse shoots, previews, start `/critique`, job status). Architecture must allow a future SwiftUI iPhone app against the **same** API.
5. Tailscale is installed at `/usr/local/bin/tailscale` — verify `tailscale status` before claiming connectivity.

**Exit test:** From Tyrone’s iPhone (on Tailscale), open the web UI, browse a shoot’s previews, start a job, see progress/errors, download a processed derivative — without transferring full RAW.
